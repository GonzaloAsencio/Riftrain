# SDD — Proposal

## Qué hacer

1. Escuchá qué quiere lograr el usuario
2. Si necesitás contexto actual del código, explorá los archivos relevantes
3. Definí:
   - **Intento**: qué problema resuelve este cambio, en una frase
   - **Alcance**: qué entra y qué NO entra en este cambio
   - **Enfoque**: ideas técnicas de alto nivel, sin profundizar en implementación
4. Si el cambio parece muy grande, proponé dividirlo en cambios más chicos
5. Preguntá: "¿Querés ajustar algo o seguimos con las specs?"

## Formato de salida

```markdown
## Proposal: [nombre del cambio]

### Intento
...

### Alcance
- Incluye: ...
- No incluye: ...

### Enfoque
...
```
